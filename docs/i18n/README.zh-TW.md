# AI-Lex

**把產品事實、規則依據和整改行動串成一條清楚的審查路徑。**

AI-Lex 是面向 AI 產品團隊的合規工作流原型。它從產品描述和結構化問答出發，把功能、資料處理、規則匹配、風險發現與文件草案放進同一工作臺，幫助產品經理、開發者和審查人員圍繞同一組事實討論上線準備情況。當前以中國法規場景研究與演示為主，保留規則路徑和人工複核環節。

## 適合誰使用

- 產品經理：在需求和方案階段整理產品事實、識別待確認事項。
- 開發與技術負責人：把資料、模型和部署方式對應到需要檢查的功能環節。
- 合規與法務審查人員：核對引用依據、適用條件與整改草案。

## 7 個核心功能

### 1. 引導式風險初篩

透過 10 道問題記錄產品型別、AI 使用、個人資訊、使用者內容和跨境場景，再按回答觸發補充追問。 得到政策、行業、產品與資料四個維度的風險簡報，以及後續需要核實的事項。

**目前：** 規則原型可執行；結果用於初篩。

### 2. 結構化合規評審

填寫行業、技術路徑、使用者範圍、資料處理和部署區域，檢視命中的規則、觸發原因與風險分級。 將散落的產品事實轉成可討論的評審條目、整改建議和備案判斷草案。

**目前：** 已實現；部署區域缺失保留為未知。

### 3. 自然語言需求分析

輸入一段產品需求，透過分解、規則匹配與缺口分析組織報告；另提供需要伺服器端金鑰的模型輔助分析路徑。 檢視需求涉及的活動、義務和缺口，追蹤結論從哪些產品描述與規則產生。

**目前：** 規則管道可用；外部模型按配置啟用。

### 4. 法規引用與檢索 API

分析頁可展開匹配法規、檢視條款和引用關係；開發者可透過檢索 API 按關鍵詞、類別或嚴重程度查詢內建法規與條款。 從某個風險條目回到對應依據，便於審查人員核對原文、適用條件和版本。

**目前：** 引用展示與檢索 API 已實現；尚無獨立法規搜尋頁面，收錄資料需持續核驗。

### 5. 文件草案與模擬備案材料

將產品名稱、公司資訊等填入使用者協議、隱私政策和 AI 服務說明模板，並提供模擬備案材料生成入口。 形成可供編輯的文件初稿與材料準備清單，保留待確認欄位供人工補充。

**目前：** 模板生成可用；Mock 材料不是正式申報。

### 6. 示例產品工作區

預設 AI 營銷、內容生成與陪伴三個案例，可切換產品上下文，觀察相同流程如何面對不同業務。 用具體案例學習各頁面之間的關係，再判斷哪些事實需要為自己的產品補齊。

**目前：** 演示工作區；尚非多租戶協作管理。

### 7. 日曆與歷史記錄預覽

日曆展示任務、備案節點和法規事件的組織方式；歷史頁按示例工作區呈現風險簡報、評審和文件記錄。 預覽持續合規管理的使用路徑，理解任務和審查成果應該如何歸檔與回看。

**目前：** 當前使用預設演示資料，不是真實提醒或審計日誌。

## 從開始到結果

1. 選擇示例產品或填寫自己的產品描述，明確目標使用者、資料與部署場景。
2. 完成風險初篩或結構化評審；缺失事實先補齊，再判斷規則是否適用。
3. 檢視需求分析、風險條目與引用依據，整理需要改進的功能和材料。
4. 生成文件草案，交由相應審查人員核實、修改並確認後再使用。

## 目前完成程度

- 研究與演示階段：初篩、規則評審、分析報告和模板生成已具備程式碼實現。
- 示例工作區、日曆和歷史頁用於演示；認證、持久化與外部模型在示例配置中預設關閉。
- 介面提供簡體中文、繁體中文與 English，並保留語言選擇；原始法源與已有生成文件保持原文。

## 快速開始

Node.js 20。複製 .env.example 為 .env.local，先保留示例功能開關為 false；未配置模型時，在需求分析頁選擇「規則引擎」模式。模型分析需另配置伺服器端金鑰並將 FEATURE_LLM 設為 true。資料庫遷移不屬於普通啟動步驟。

```bash
npm ci
# Copy .env.example to .env.local
npm run dev
# http://localhost:3000
npm test
npm run build
```

## 使用邊界

- 規則命中不等於已履行義務，風險分數不等於法律結論；需結合適用法域、最新法源和真實產品事實複核。
- 不將內建收錄數量、演示時間或模型輸出寫成覆蓋率、準確率與效率承諾。
- 當前沒有已驗證的團隊許可權、長期審計記錄或正式監管申報閉環；這些與原型頁面分開建設。
