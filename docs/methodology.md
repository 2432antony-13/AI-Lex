# 可审计合规方法

AI-Lex 不把大模型的“合理猜测”直接当作法律事实，而是把事实、规范、推理和结论分开管理。

## 四类对象

| 对象 | 内容 | 控制要求 |
| --- | --- | --- |
| 事实 | 用户确认的信息或可核验材料 | 标记来源、时间与缺失项 |
| 规则 | 法律规范、监管文件和内部政策 | 记录法域、版本和适用条件 |
| 推理 | 事实与规则之间的匹配过程 | 允许复核、异议和状态变更 |
| 输出 | 风险项、建议与文档草案 | 标明依据、限制与责任主体 |

## 关键机制

1. **禁止静默补全事实**：材料不足时保留“未知”，通过追问或人工补证解决。
2. **依据与结论绑定**：每个风险项应能回溯到输入事实和候选规则。
3. **模型输出降级**：生成内容属于建议或草案，不能覆盖已确认事实。
4. **法域隔离**：不同法域的规则分别维护，跨法域比较需要显式标记。
5. **人在回路**：高风险判断、规则更新和对外交付必须设置人工确认点。

## 与 MoE 研究的关系

未来可把不同法域、任务或证据类型映射为专业专家模块，由路由层选择参与分析的专家。这里的 MoE 是可研究的模型能力层，不等同于法律责任分配机制。无论底层采用稠密模型还是 MoE，事实账本、来源追溯、规则版本和人工复核仍是可审计性的基础。
