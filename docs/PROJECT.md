# AI-Lex 项目章程

采用日期：2026-10-27。项目所有者与产品决定：2432antony-13；当前实施：获授权 Agent。自查、独立复核和用户验收分别记录。当前建议阶段：验证；业务期限、投入预算和独立验收人尚未指定，不虚填承诺。

## 用户与结果

服务对象：设计、开发和上线 AI 产品的团队与审查人员。产品目标：将已知产品事实、适用规则、风险依据、草案和人工复核关联起来。用户价值尚未通过本轮测量，本文件不声称准确率或效率提升。

## 本轮管理范围

用户于 2026-10-27 要求五个现有 GitHub 仓库按既定规范建设。本轮交付是章程、任务与里程碑、协作规则、按项目适配的检查/验收、来源资产和交付交接。功能建议进入有验收的待办，不自动扩大为跨仓集成。暂不新建仓库，不纳入 JEV 或其他本地项目。

## 完成条件

- 从项目入口找到当前任务、负责人、范围、依赖和可观察验收。
- 代码/文档变更通过短分支和 PR，检查结果绑定实际提交；规则是否由平台强制单独记录。
- 产品验收按 [质量矩阵](governance/QUALITY.md)；未执行、失败、通过分别记录。
- 交付给出版本、渠道、结果和恢复限制；治理文档进入默认分支不代表产品整体合格。
- 新执行者能从 [交接](governance/HANDOVER.md) 找到下一动作，不依赖聊天猜测。

## 约束与资料

缺失事实应显式保留；模型生成与规则匹配均需可查依据；中国规则与 DataTrace HK/SG 数据不得直接混用。

当前渠道：现有 Next.js 应用；实际生产域名和部署版本尚待核对，治理文档通过本仓库默认分支交付。 截止时间和新外部费用未承诺；真实模型调用、邮件或数据迁移依具体任务范围执行。业务结果不足时暂停扩展功能，先解决关键未知。

## 唯一事实源

[Issues](https://github.com/2432antony-13/AI-Lex/issues) 保存任务与验收；PR 保存差异；Actions 保存运行；本仓库保存产品规格、资产与交付证据。跨仓索引在既有私有 workspace-governance。任务状态统一在[私有管理看板](https://github.com/users/2432antony-13/projects/1)的 Status 字段维护，阻塞使用 Blocked / Blocker 字段；Issue 正文保留验收与解除条件。旧 status/blocked 标签停止作为状态源。

## 采用与复查

采用用户提供 project-governance v1.0.0 的核心信息结构，按本仓适配；原包的历史账号、批准、资源 ID 和排期不适用。默认分支 `main`。大范围架构/模型/数据/渠道变化在任务记录取舍，普通修复不另造冗余表格。产品范围变化或一次交付结束时复查本章程。
