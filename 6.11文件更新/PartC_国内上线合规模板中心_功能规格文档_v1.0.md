## 一、模块定位

**服务阶段：** 开发完成 → 正式对外提供服务前
**核心问题：** 上线前需要准备哪些文本和材料？
**核心价值：** 帮助团队从"知道有义务"走到"能够提交和留档"——根据产品类型与功能配置，自动生成可直接使用的合规文件包，覆盖前台展示文本、监管备案材料和内部治理制度三类。
**主要输出：** 《国内上线合规文档包》（前台展示包 + 备案申报包 + 内部留档包）

### 与 Part A/B 的衔接关系

```
Part A 识别合规风险
    │
    └─ 输出风险条目 + 数据类型清单 + 行业场景 + 跨境标志
              ↓
Part B 开发期完成合规动作 + 生成草稿文档
    │
    └─ 输出：隐私政策草稿 / 用户协议草稿 / PIPIA草稿 / SDK清单草稿
              ↓
Part C 上线前格式规范化 + 补充模板 + 打包交付
    │
    ├─ 从 Part B 导入草稿 → 补全 → 版本化 → 前台展示包
    ├─ 根据备案触发条件 → 生成备案申报材料包
    └─ 根据行业/功能配置 → 生成内部治理制度包
              ↓
    《国内上线合规文档包》（可直接提交/部署/留档）
```

**Part C 与 Part B 的分工边界：**
- Part B 负责"动态评审"——开发过程中识别问题、跟踪整改
- Part C 负责"静态交付"——生成可提交、可公示、可留档的最终版文件

## 二、配置表单（触发入口）

用户进入 Part C 时，首先完成产品配置表单。系统根据配置结果自动生成"必备文件 / 建议文件 / 可能触发的备案事项"三档清单。

> **从 Part B 导入：** 若已完成 Part B 评审，点击「从 Part B 导入配置」可自动预填全部字段，用户确认后直接进入文档生成。若 Part B 存在高优先级合规动作尚未完成，系统将显示警示（如"Part B 中有 X 项高优先级合规动作尚未完成，生成的文件可能存在内容缺口，建议完成后再导入"），并提供「继续导入」或「返回 Part B 完成」两个选项。

### 2.1 配置字段

| 字段 | 输入类型 | 必填 |
|------|---------|------|
| 产品形态 | 多选：App / 小程序 / 网站 / API服务 / 多形态组合 | 是 |
| 是否收集个人信息 | 是 / 否 | 是 |
| 调用设备权限 | 多选：摄像头 / 麦克风 / 位置 / 相册 / 通讯录 / 无 | 条件必填 |
| 是否使用生成式AI | 是 / 否 | 是 |
| 是否调用第三方大模型API | 是（可填写模型名称）/ 否 | 是 |
| 是否自部署开源大模型 | 是（可填写模型名称）/ 否 | 是 |
| 是否使用推荐算法 | 是 / 否 / 不确定 | 是 |
| 是否使用深度合成（换脸/声音克隆/数字人） | 是 / 否 | 是 |
| 是否面向公众提供服务 | 是 / 否 | 是 |
| 是否面向未成年人（或不限制未成年人使用） | 是 / 否 / 不确定 | 是 |
| 是否使用用户数据训练/微调模型 | 是 / 否 | 是 |
| 是否接入第三方SDK | 是 / 否 | 是 |
| 是否涉及数据跨境（用户数据存储或传输至境外） | 是 / 否 / 不确定 | 是 |
| 行业场景 | 多选：医疗健康 / 教育 / 金融 / 招聘 / 内容平台 / 通用工具 / 其他 | 是 |
| 预计注册用户/月活规模 | 单选：1万以下 / 1万—100万 / 100万以上 | 是 |
| 是否具有舆论属性或社会动员能力 | 是 / 否 / 不确定 | 是 |

### 2.2 三档输出矩阵

系统根据配置字段，按以下逻辑分配文档至三档：

| 配置条件 | 必备文件 | 建议文件 | 可能触发备案 |
|---------|---------|---------|------------|
| 面向公众提供服务=是 | 用户协议 | — | ICP备案/App上架核查 |
| 收集个人信息=是 | 隐私政策、个人信息收集清单 | 数据处理活动记录 | — |
| 接入第三方SDK=是 | 第三方信息共享清单 | — | — |
| 面向未成年人=是/不确定 | 未成年人隐私政策 | — | — |
| 使用生成式AI=是 | AI服务特别说明 | AI内容治理制度 | 生成式AI服务备案（具有舆论属性时） |
| 使用推荐算法=是，且满足以下任一：具有舆论属性或社会动员能力，或预计用户超100万 | 算法备案材料包 | 算法安全主体责任制度 | 算法推荐备案 |
| 使用深度合成=是 | 深度合成服务告知模板 | — | 深度合成备案（具有舆论属性时） |
| 使用用户数据训练模型=是 | 训练数据与知识库治理 | — | 安全评估（备案前置要求） |
| 收集个人信息=是（任何规模） | 个人信息保护内部制度 | — | — |
| 涉及数据跨境=是 | 隐私政策跨境传输章节（须单独说明） | 数据出境合规方案选择说明 | 数据出境安全评估（向境外提供100万人以上个人信息时）/ 个人信息出境标准合同（10万—100万人时） |
| 行业场景含金融/医疗/政务，或用户超100万 | — | 等级保护测评核查清单（参考） | 网络安全等级保护定级备案 |

> **说明：** "必备文件"为法规明确要求、缺失即违规；"建议文件"为无强制要求但构成合规基础设施的关键文件；"可能触发备案"为需进一步核查是否达到监管申报门槛的事项。

## 三、C1 — 前台法律文本模板

> 用于 App、小程序、网站和 AI 工具的用户可见页面或注册流程，共 6 个模板。

### 3.1 用户协议模板

**适用场景：** 面向公众提供服务的所有产品形态

> **从 Part B 导入：** 若已完成 Part B 评审，系统自动导入《用户服务协议要点清单草稿》中已确认的服务描述、用户行为规范和联系方式等字段，用户在此基础上补充 AI 特定条款后直接生成完整协议。

**模板结构（含 AI 特定条款）：**

| 章节 | 主要内容 | AI 产品特别要点 |
|------|---------|--------------|
| 第一条：服务内容 | 服务定义、适用范围、版本说明 | 明确 AI 功能边界与能力范围 |
| 第二条：账号注册与安全 | 注册资格、实名要求、账号保管责任 | 如涉及年龄限制须明确核验方式 |
| 第三条：用户行为规范 | 允许用途、禁止行为清单 | 禁止利用AI生成违法内容的专项条款 |
| 第四条：知识产权 | 平台内容归属、用户内容授权 | AI生成内容著作权归属说明；用户输入内容的授权范围 |
| 第五条：AI 输出边界与免责 | 输出准确性限制、不构成专业建议声明 | 医疗/法律/金融场景须单独强化免责条款 |
| 第六条：自动化决策说明 | 使用方式说明、申诉渠道告知 | 对用户权益有重大影响时须提供拒绝自动化决策的权利 |
| 第七条：责任限制 | 服务中断、第三方内容、间接损失 | AI内容错误、模型幻觉的责任边界 |
| 第八条：协议变更 | 变更通知方式、生效时间 | 模型更新/功能变更时协议更新机制 |
| 第九条：争议解决 | 适用法律、管辖法院/仲裁机构 | 推荐：被告住所地法院或北京仲裁委 |
| 第十条：联系方式 | 客服渠道、投诉举报入口 | 须设置便捷举报入口（生成式AI监管要求） |

**生成方式：** 结构化模板，用户在每章节填写产品特定信息（产品名称/服务内容/联系方式等），系统自动合并生成完整协议。

### 3.2 隐私政策模板

**适用场景：** 收集个人信息=是

**模板结构：**

| 章节 | 自动填写内容 | 用户操作 |
|------|------------|---------|
| 一、我们收集的信息 | 从配置表单的「个人信息类型」字段自动汇总 | 确认/补充 |

| 六、跨境传输 | 如 Part B 标记了跨境标志，自动插入；否则提示确认 | 确认/补充 |
| 七、Cookie 与追踪技术 | 网站/App 产品自动插入；API 产品提示是否适用 | 确认/修改 |

| 十、隐私政策更新 | 固定条款，含更新通知机制 | 确认 |
| 十一、联系我们 | 用户填写 | 必填 |

**法规对齐标注：** 每章节标注对应法规要求（《个人信息保护法》第13条/第17条/第19条等），方便法务核查。

## 四、C2 — 监管/备案申报模板

> 支持三类备案申报材料的生成（4.1 算法推荐备案 / 4.2 生成式AI备案 / 4.3 深度合成备案）+ 一类上架核查清单（4.4）+ 一类数据出境合规材料包（4.5），共五类，按需触发，每类包含完整材料清单与模板文件。

### 4.1 算法推荐备案材料包

**触发条件：** 使用推荐算法=是，且满足以下任一：具有舆论属性或社会动员能力，或预计用户超100万
**法规依据：** 《互联网信息服务算法推荐管理规定》第24条
**备案平台：** 互联网信息服务算法备案系统（beian.cac.gov.cn）
**备案时限：** 提供服务之日起10个工作日内

**材料包内容：**

| 材料名称 | 生成方式 | 核心内容 |
|---------|---------|---------|
| 算法备案承诺书 | 固定模板，填写主体信息 | 声明遵守《互联网信息服务算法推荐管理规定》各项义务 |
| 算法安全主体责任说明 | 引导式问答生成 | 责任人信息、安全管理制度承诺、投诉举报渠道 |
| 算法安全自评估报告 | 结构化模板（见4.1.1） | 算法基本原理、应用场景、数据使用、影响评估、安全措施 |
| 拟公示内容模板 | 固定模板，填写具体参数 | 面向用户的算法推荐公示（推荐标准、主要参数等） |
| 备案表填写指引 | 说明文档 | 各字段填写规范与示例 |

#### 4.1.1 算法安全自评估报告结构

```
一、算法基本情况
  ├─ 算法名称与版本
  ├─ 算法类型（协同过滤/内容推荐/排序算法等）
  └─ 适用产品功能模块

二、应用场景说明
  ├─ 推荐逻辑与触发条件
  ├─ 影响用户范围
  └─ 是否用于差异化定价或用户分层

三、数据使用说明
  ├─ 输入特征类型
  ├─ 训练数据来源与合法性
  └─ 个人信息处理方式

四、用户权益保障
  ├─ 是否提供「不针对个人特征」的内容选项
  ├─ 关闭个性化推荐的功能入口
  └─ 申诉与人工复核机制

五、安全防护措施
  ├─ 防止算法歧视的技术措施
  ├─ 日志记录与审计机制
  └─ 安全事件应急预案

六、年度自评估结论
```

```
           │     ├─ 数据处理活动记录（RoPA）.xlsx    │
           │     ├─ AI内容治理制度.docx             │
           │     ├─ 算法安全主体责任制度.docx        │
           │     └─ 训练数据与知识库治理表.xlsx      │
           └─────────────────────────────────────┘
```

### 6.2 文档生成方式说明

| 生成方式 | 适用文档 | 用户操作量 |
|---------|---------|----------|
| 自动填充 | 从 Part B 导入的字段可自动填入隐私政策、SDK清单等 | 最低（仅需确认） |
| 填空式 | 用户协议、AI服务特别说明等结构固定的文档 | 低（填写产品特定字段） |
| 引导式问答 | 算法安全自评估报告、安全评估报告框架 | 中（逐步回答问题） |
| 结构化表格 | 数据处理活动记录、各类核查表 | 中（逐行填写） |
| 固定模板 | 算法备案承诺书、ICP上架清单等 | 低（填写主体信息） |

### 6.3 版本管理

- 每份文档生成后自动分配版本号（格式：v1.0 / 2026-06-11）
- 修改后另存为新版本，历史版本保留（不覆盖）
- 文档列表显示：文档名称 / 版本号 / 生成日期 / 状态（草稿/确认版/已提交）
- 支持导出完整文档包（PDF+Word，含版本号水印）

### 7.1 主流程页面

### 7.2 交互细节

- 配置表单字段附「什么是XX？」帮助说明（如：如何判断是否具有舆论属性）

- 支持多人协作：不同文档可指派给不同负责人完成填写

### 7.4 导出文件版本标注规格

所有从 Part C 导出的文件（PDF / Word / HTML），在以下位置附加版本标注：

| 文件格式 | 标注位置 | 标注内容 |
|---------|---------|---------|
| PDF | 每页页脚居中 | `版本 [X.X] · 生成日期 [YYYY-MM-DD]` |
| Word（.docx） | 文档属性（自定义字段，不影响正文排版） | 同上 |
| HTML | `<meta>` 标签 | 同上 |
| Excel（.xlsx） | 首行冻结行，浅灰色背景 | 同上 |

> **说明：** 版本标注仅记录生成时间和版本号，供团队内部版本管理使用，不在文件正文中添加任何提示性文字。Word 版导出后可直接作为正式文件使用，无需手动清理。
