## 一、模块定位

**服务阶段：** 立项确认后 → 测试上线前
**核心问题：** 开发过程中，每个技术决策和功能实现是否满足合规要求？
**核心价值：** 将 Part A 识别出的风险转化为开发团队可执行的合规动作，贯穿整个开发周期，保证上线前合规状态可知、可追、可证明。
**主要输出：** 《开发期合规评审报告》（进度跟踪版）+ 各类合规文档（隐私政策/用户协议/PIPIA/备案材料清单）

### 与 Part A 的闭环关系

```
Part A 风险识别
    │
    ├─ 风险条目（政策/行业/数据/交互）
    │        ↓
    │   自动导入 Part B
    │        ↓
    ├─ 每条风险 → 对应具体开发动作（合规清单条目）
    │        ↓
    │   开发团队逐项完成，标记状态
    │        ↓
    └─ 完成的动作 → 生成对应合规文档（隐私政策/PIPIA/备案材料）
                         ↓
                    文档反向关联风险条目（可溯源）
```

**原则：** Part A 的每一条风险，在 Part B 中必须有对应的处理记录，不允许断档。

## 二、模块架构

Part B 包含两条主轨：

| 主轨 | 适用法域 | 触发条件 |
|------|----------|----------|
| **B-CN：中国合规主轨** | 中国大陆法律体系 | 所有用户默认进入 |
| **B-EU：欧盟合规子模块** | GDPR + EU AI Act | 服务地区包含欧盟时自动解锁 |

两条主轨共用同一个项目空间，共享用户输入数据和文档存储，但评审清单、文档模板、判断逻辑各自独立。

## 三、B-CN：中国合规主轨

### 3.1 评审启动

#### 启动方式 A：从 Part A 导入（主要路径）

1. 在 Part A 报告界面点击「进入开发期评审」
2. 系统自动导入以下数据包：

| 导入字段 | 来源 |
|---------|------|
| 产品名称/描述/目标用户/服务地区 | Part A Step 1 |
| 功能特征（AI能力/深度合成/推荐算法等） | Part A Step 2 |
| 数据类型清单/行业场景/跨境标志 | Part A Step 3 |
| 各维度风险等级及具体风险条目列表 | Part A 风险识别引擎输出 |
| 数据处理活动识别矩阵 | Part A Section 7.1.1 |

3. 系统显示导入预览，用户确认后正式创建 Part B 评审项目
4. 每个 Part A 风险条目自动生成对应 Part B 待处理动作

#### 启动方式 B：独立启动（未做 Part A 的团队）

- 直接进入 Part B 表单，填写与 Part A Step 1-3 相同的字段
- 系统在后台执行一次简化版风险识别，生成初始动作清单
- 报告中标注「未关联 Part A，风险识别可能不完整，建议补做 Part A 评估」

### 3.3 文档生成中心

> 合规清单中的动作完成后，系统自动解锁对应文档模板的生成功能；生成文档反向关联到对应清单条目，形成证明闭环。

#### 3.3.1 文档列表

| 文档名称 | 生成方式 | 触发条件 | 关联清单维度 |
|---------|---------|---------|------------|
| **隐私政策**（中文版） | 填空式，AI辅助完善 | 收集个人信息=是 | 同意与告知 |
| **用户服务协议要点清单** | 结构化模板 | 面向公众提供服务 | 同意与告知 |
| **未成年人隐私政策草稿** | 填空式，基于隐私政策模板扩展 | 面向未成年人=是/不确定，或行业场景含教育/未成年人 | 同意与告知 |
| **第三方信息共享清单草稿**（含SDK及第三方API） | 自动汇总 | 接入第三方SDK=是，或调用第三方大模型API=是 | 第三方依赖 |
| **个人信息保护影响评估报告（PIPIA）** | 引导式问答生成 | 处理敏感信息/大规模/自动化决策 | 数据架构 |
| **生成式AI服务备案申请材料清单** | 条件生成 | 使用生成式AI且面向公众 | — |
| **算法推荐备案申请材料清单** | 条件生成 | 具有舆论属性或用户超100万 | — |
| **深度合成备案申请材料清单** | 条件生成 | 使用深度合成且面向公众 | — |
| **数据安全风险评估报告框架** | 模板+引导 | 医疗/金融/政务行业场景 | 数据架构 |
| **医疗AI合规自查清单** | 条件生成 | 行业场景含医疗健康，且AI功能涉及临床决策场景（见3.4.4） | 专项评审（3.4.4） |
| **金融AI合规核查清单** | 条件生成 | 行业场景含金融，且AI功能涉及金融业务场景（见3.4.5） | 专项评审（3.4.5） |

> **Part B 备案材料清单 vs. Part C 备案材料包的分工：**
> - Part B 生成的"备案申请材料清单"是**核查清单**——列出备案所需准备的全部材料项目、提交要求和注意事项，帮助开发团队在开发期提前做好材料准备。
> - Part C 生成的"备案材料包"是**完整内容文件**——包含每份材料的完整正文（如安全评估报告、备案承诺书等），可直接提交给监管机构。
> - 典型路径：Part B 清单 → 开发期按清单逐项准备 → Part C 导入配置 → 生成完整材料包 → 提交备案。

| 模块 | 自动填写内容 | 用户操作 |
|------|------------|---------|
| 信息收集范围 | Part A Step 3 收集的个人信息类型 | 确认/补充 |
| 收集方式 | 基于功能特征推断（注册/使用中收集/SDK采集） | 确认/修改 |
| 使用目的 | 基于行业场景和AI能力推断 | 确认/修改 |
| 共享第三方 | Part B 第三方SDK清单自动汇总 | 确认/补充 |
| 跨境传输 | Part A 跨境标志 + Part B 第三方API合规核查结果 | 确认/补充 |

| 联系方式 | 用户填写 | 必填 |

#### 3.3.3 PIPIA 引导式生成

**《个人信息保护影响评估报告（PIPIA）》按《个人信息保护法》第55-56条要求，分五步引导完成：**

```
Step 1：处理活动描述
  └─ 自动导入 Part A Section 7.1.1 数据处理活动识别矩阵
  └─ 用户确认/补充

Step 2：必要性与合法性论证
  └─ 每项数据处理活动，引导用户填写：
     「为什么需要收集这类数据？」
     「法律依据是什么（同意/合同/法定义务/正当利益）？」

Step 3：风险识别
  └─ 自动导入 Part A 数据合规维度风险条目
  └─ 用户补充开发期新发现的风险

Step 4：控制措施
  └─ 自动关联 Part B 合规清单中已完成的技术措施
  └─ 用户补充管理措施

Step 5：评估结论与复核计划
  └─ 系统生成结论框架
  └─ 用户确认后生成完整 PDF 报告
```

### 3.4 专项评审（按需触发）

以下专项评审模块在满足触发条件时，在评审项目中自动解锁并提示用户进入。

#### 3.4.1 算法安全专项

**触发条件：** 使用推荐算法=是，或自动化决策影响用户权益=是

**评审内容：**
- 算法基本原理与逻辑说明文档（供备案使用）
- 算法对用户的影响范围说明（内容推荐/价格/资质筛选等）
- 防止算法歧视的设计说明（是否存在性别/地域/年龄等维度偏向）
- 算法可解释性设计（用户可查看推荐原因）
- 用户选择关闭个性化推荐的功能入口
- 算法安全年度自评估计划安排

**输出：** 《算法安全自评估报告》（符合《互联网信息服务算法推荐管理规定》**第27条**安全评估要求）

> **与 Part D 义务日历的衔接：** Part B 算法安全专项面向所有使用推荐算法的产品（开发期一次性完成）；Part D 的算法安全年度自评估义务仅针对**具有舆论属性或社会动员能力**的服务提供者（法规明确的年度义务主体），用户超100万时也建议参照执行。不具备舆论属性且用户未超百万的产品，虽无法规明确的年度自评估强制要求，仍建议参照自评估报告框架定期复核。

#### 3.4.2 数据出境合规路径专项

**触发条件：** 涉及数据跨境=是

**路径选择引导：**

```
系统根据以下条件自动推荐合规路径：
（依据：《促进和规范数据跨境流动规定》（2024）第7条，已修订《数据出境安全评估办法》第4条门槛，以新规为准）

条件1：关键信息基础设施运营者向境外提供个人信息或重要数据；
       或非关键基础设施运营者累计向境外提供100万人以上个人信息（不含敏感信息）；
       或累计向境外提供1万人以上敏感个人信息
    → 推荐路径：国家安全评估（数据出境安全评估）
    → 预计周期：60-90个工作日
    → 提示：须提前启动，建议上线前6个月开始准备
    → 依据：《数据出境安全评估办法》第4条 + 《促进和规范数据跨境流动规定》第7条

条件2：向境外提供10万人以上不足100万人个人信息（不含敏感个人信息）
    → 推荐路径：个人信息出境标准合同（SCCs-CN）
    → 预计周期：签署后30日内向网信办备案
    → 依据：《个人信息出境标准合同办法》第2条、第12条；《促进和规范数据跨境流动规定》第8条

条件3：通过个人信息保护认证机构认证（适合集团内传输）
    → 推荐路径：个人信息保护认证
    → 预计周期：依认证机构安排
    → 依据：《网络数据安全管理条例》（2025）第35条第（二）项

条件4：向境外提供不足10万人个人信息（不含敏感个人信息），且不涉及重要数据
    → 当前可豁免安全评估、标准合同、认证要求，但须在隐私政策中告知
    → 依据：《促进和规范数据跨境流动规定》（2024）第5条第（四）项

【特别说明】重要数据出境：
    → 无论规模，非关键基础设施运营者向境外提供重要数据，须经国家安全评估
    → 依据：《数据安全法》第三十一条
    → 提示：重要数据认定须参照行业主管部门的数据目录；如不确定是否属于重要数据，建议保守认定并咨询专业法律意见
```

**输出：** 《数据出境合规方案选择说明》+ 对应路径的材料准备清单

#### 3.4.3 等级保护定级专项

**触发条件：** 行业场景含金融/医疗/政务，或预计用户超100万

**评审内容：**
- 系统定级建议（基于行业和数据敏感程度给出建议等级）
- 定级报告编写引导
- 备案流程说明（向属地公安机关备案）
- 测评机构选择建议
- 等保二/三级技术要求核查清单（对应开发团队需完成的技术项）

#### 3.4.4 医疗AI专项（SaMD核查）

**触发条件：** 行业场景含医疗健康，且AI功能涉及疾病诊断/病情评估/治疗建议/健康风险预测等临床决策场景

**评审内容：**

| 核查项 | 要求 | 法规依据 |
|--------|------|---------|
| 是否构成医疗器械软件（SaMD）判断 | 基于功能描述判断产品是否符合"软件即医疗器械"定义（提供诊断/治疗辅助的独立软件属于医疗器械） | 《医疗器械监督管理条例》第103条；国家药监局《医疗器械软件注册审查指导原则》 |
| SaMD 类别判断 | 依据预期用途和风险等级：一类（低风险，仅需备案）/ 二类（中风险，需注册）/ 三类（高风险，须上市前审查） | 《医疗器械分类规则》；《医疗器械分类目录》 |
| AI免责声明充分性 | 产品声明"仅供参考，不构成诊断意见"是否足以规避SaMD认定（注：该声明不改变功能性质，不必然豁免监管） | 国家药监局软件注册审查指导意见 |
| 数据安全特殊要求 | 医疗数据分级（电子病历=核心数据，健康档案=重要数据）；存储于等保三级以上系统 | 《数据安全法》第21条、《网络安全法》 |

> **重要提示：** 若初步判断可能构成SaMD，系统将显示高风险警示并建议在开发前向具有医疗行业经验的法律顾问确认产品定性。SaMD注册程序通常需要6—24个月，须在产品方向确定时即启动。不构成SaMD的医疗AI产品仍须遵守健康数据敏感个人信息保护要求。

**输出：** 《医疗AI合规自查清单》（含SaMD判断矩阵 + 数据安全特殊要求清单）

#### 3.4.5 金融AI专项（持牌合规核查）

**触发条件：** 行业场景含金融，且AI功能涉及信贷审批/投资建议/保险核保/资产管理/风险评分等金融业务

**评审内容：**

| 核查项 | 要求 | 法规依据 |
|--------|------|---------|
| 是否触发持牌要求 | AI提供投资建议（须证券投资顾问资质）/信贷审批（须网络贷款业务资质）/保险核保（须保险经营许可）等 | 《证券法》《银行业监督管理法》《保险法》 |
| 银行/保险AI系统上线前审查 | AI系统须通过数据安全审查；建立退出替代方案和应急预案 | 《银行保险机构数据安全管理办法》第50—52条 |
| 算法模型可验证性 | 模型须可验证、可审核、可追溯；信贷/投资类AI须提供拒绝原因说明 | 《银行保险机构数据安全管理办法》第52条；《个人信息保护法》第24条 |
| 证券AI风险管控 | 业务日志保存5年以上；不得以生物特征作为唯一身份认证方式 | 《证券期货业网络和信息安全管理办法》第18条、第35条 |
| 金融数据出境限制 | 账户资金/交易流水/征信数据不得出境 | 《数据安全法》第21条、中国人民银行相关规定 |

> **重要提示：** 无证经营金融业务可能面临刑事责任，建议在产品方向确认前优先确认是否需要持牌，此步骤必须早于开发启动。

**输出：** 《金融AI合规核查清单》（含持牌要求判断表 + AI系统合规要求清单）

## 四、B-EU：欧盟合规子模块

> **适用场景：** Part A 服务地区选择包含欧盟，系统自动解锁本模块。
> **法律范围：** GDPR（通用数据保护条例）+ EU AI Act（欧盟人工智能法案，2024年正式生效）

### 4.1 模块启动

当 Part A 服务地区 = 欧盟时，在 Part B 项目空间中显示「EU合规」选项卡，与 B-CN 并列。两个模块共享产品基本信息和数据类型清单，评审清单和文档模板独立运行。

### 4.2 GDPR 合规清单

#### 核心处理原则核查

| 核查项 | 要求 | 缺失风险 |
|--------|------|---------|
| 合法性基础（Lawful Basis）确认 | 每项数据处理活动必须有明确的合法性基础（同意/合同/法定义务/正当利益/重大利益/公共任务） | 最高处罚：全球年营业额4%或2000万欧元（取高） |
| 数据主体权利实现 | 访问权/更正权/删除权/可携带权/反对权/限制处理权 | 同上 |
| 隐私设计原则（Privacy by Design & Default） | 数据最小化/访问控制/默认保护 | 同上 |
| 数据保留期限限制 | 明确每类数据的保留期限，超期删除 | 同上 |
| 第三方数据处理协议（DPA） | 与所有处理欧盟用户数据的第三方签署DPA | 同上 |
| 跨境传输机制（SCCs/BCRs/Adequacy Decision） | 向欧盟以外传输数据须采用合规机制 | 同上 |
| 数据保护官（DPO）任命 | 大规模处理敏感数据或公共机构须任命 | 最高处罚：年营业额2%或1000万欧元 |
| 数据保护影响评估（DPIA） | 高风险处理活动（大规模/自动化决策/新技术）须事先评估 | 同上 |
| 个人数据泄露通知机制（72小时） | 发生个人数据泄露须72小时内通知监管机构 | 同上 |
| 记录处理活动（RoPA） | 雇员≥250人或高风险处理须维护处理活动记录 | 同上 |

#### GDPR 特别关注：AI场景下的自动化决策

| 要求 | 法律依据 | 实现方式 |
|------|---------|---------|
| 禁止完全自动化决策产生重大法律影响，除非有明确豁免 | GDPR第22条 | 设计人工介入环节；或取得用户明确同意；或作为合同履行必要步骤 |
| 用户有权要求人工复核 | GDPR第22(3)条 | 提供申诉入口，承诺人工复核响应时限 |
| 向用户提供有意义的自动化逻辑说明 | GDPR第13/14条 | 隐私政策中说明算法逻辑和主要参数 |

### 4.3 EU AI Act 合规清单

> **注：** EU AI Act 于2024年8月正式生效，2025年2月起禁止类AI条款适用，**2025年8月起通用目的AI（GPAI）条款适用**（含透明度要求、技术文档、版权合规声明），2026年8月起高风险AI系统条款正式适用。以下按风险分类框架梳理。

#### Step 1：AI系统风险分类判断

| 类别 | 判断条件 | 合规要求强度 |
|------|---------|------------|
| **不可接受风险（禁止）** | 操纵人类行为/利用弱势群体/社会评分/实时生物识别（执法场景）等 | 绝对禁止，无豁免 |
| **高风险AI系统** | 用于：招聘筛选/信贷评分/教育评估/关键基础设施/执法/司法/医疗器械/重要安全组件 | 强制合规要求（见4.3.2） |
| **通用目的AI系统（GPAI）** | 大型基础模型/可多场景使用的生成式AI | 透明度要求+系统性风险评估（见4.3.3） |
| **有限风险** | 聊天机器人/深度合成/情感识别等 | 透明度告知义务 |
| **低风险** | 垃圾邮件过滤/AI推荐等 | 自愿行为守则 |

系统根据 Part A 功能特征输入自动判断风险类别，并在报告中标注。

#### 4.3.2 高风险AI系统合规清单

| 合规要求 | 内容 | 适用节点 |
|---------|------|---------|
| 风险管理体系 | 建立并维护贯穿产品生命周期的风险管理文档 | 开发初期 |
| 数据治理 | 训练/验证/测试数据集的质量标准、偏见检测记录 | 开发初期 |
| 技术文档 | 系统架构/训练方法/性能指标/测试结果完整记录 | 开发中期 |
| 日志记录 | 系统运行日志，保留供监管核查 | 开发中期 |
| 透明度与信息提供 | 向用户提供AI系统的能力/局限/预期用途说明 | 上线前 |
| 人类监督 | 设计允许自然人监督和干预的机制 | 开发中期 |
| 准确性与鲁棒性 | 经过充分测试，对抗错误和操纵攻击 | 上线前 |
| 合格评估（Conformity Assessment） | 按规定自行评估或第三方审核 | 上线前 |
| CE标识与注册 | 欧盟数据库注册（适用于需注册的高风险系统） | 上线前 |

#### 4.3.3 通用目的AI（GPAI）透明度要求

**适用：** 调用或部署大型基础模型（GPT/Claude/Gemini等），或自研GPAI系统

| 要求 | 内容 |
|------|------|
| 训练数据摘要 | 公开训练数据的主要类别和来源 |
| 版权合规声明 | 说明训练数据符合欧盟版权法要求 |
| 技术文档 | 向下游使用者（企业客户）提供充分的集成文档 |
| 系统性风险评估（大型模型，≥10^25 FLOPs） | 评估对基本权利/社会稳定的系统性风险 |
