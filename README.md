# AI-Lex

**把产品事实、规则依据和整改行动串成一条清楚的审查路径。**

AI-Lex 是面向 AI 产品团队的合规工作流原型。它从产品描述和结构化问答出发，把功能、数据处理、规则匹配、风险发现与文档草案放进同一工作台，帮助产品经理、开发者和审查人员围绕同一组事实讨论上线准备情况。当前以中国法规场景研究与演示为主，保留规则路径和人工复核环节。

## 适合谁使用

- 产品经理：在需求和方案阶段整理产品事实、识别待确认事项。
- 开发与技术负责人：把数据、模型和部署方式对应到需要检查的功能环节。
- 合规与法务审查人员：核对引用依据、适用条件与整改草案。

## 7 个核心功能

### 1. 引导式风险初筛

通过 10 道问题记录产品类型、AI 使用、个人信息、用户内容和跨境场景，再按回答触发补充追问。 得到政策、行业、产品与数据四个维度的风险简报，以及后续需要核实的事项。

**当前：** 规则原型可运行；结果用于初筛。

### 2. 结构化合规评审

填写行业、技术路径、用户范围、数据处理和部署区域，查看命中的规则、触发原因与风险分级。 将散落的产品事实转成可讨论的评审条目、整改建议和备案判断草案。

**当前：** 已实现；部署区域缺失保留为未知。

### 3. 自然语言需求分析

输入一段产品需求，通过分解、规则匹配与缺口分析组织报告；另提供需要服务端密钥的模型辅助分析路径。 查看需求涉及的活动、义务和缺口，追踪结论从哪些产品描述与规则产生。

**当前：** 规则管道可用；外部模型按配置启用。

### 4. 法规引用与检索 API

分析页可展开匹配法规、查看条款和引用关系；开发者可通过检索 API 按关键词、类别或严重程度查询内置法规与条款。 从某个风险条目回到对应依据，便于审查人员核对原文、适用条件和版本。

**当前：** 引用展示与检索 API 已实现；尚无独立法规搜索页面，收录数据需持续核验。

### 5. 文档草案与模拟备案材料

将产品名称、公司信息等填入用户协议、隐私政策和 AI 服务说明模板，并提供模拟备案材料生成入口。 形成可供编辑的文档初稿与材料准备清单，保留待确认字段供人工补充。

**当前：** 模板生成可用；Mock 材料不是正式申报。

### 6. 示例产品工作区

预设 AI 营销、内容生成与陪伴三个案例，可切换产品上下文，观察相同流程如何面对不同业务。 用具体案例学习各页面之间的关系，再判断哪些事实需要为自己的产品补齐。

**当前：** 演示工作区；尚非多租户协作管理。

### 7. 日历与历史记录预览

日历展示任务、备案节点和法规事件的组织方式；历史页按示例工作区呈现风险简报、评审和文档记录。 预览持续合规管理的使用路径，理解任务和审查成果应该如何归档与回看。

**当前：** 当前使用预设演示数据，不是真实提醒或审计日志。

## 从开始到结果

1. 选择示例产品或填写自己的产品描述，明确目标用户、数据与部署场景。
2. 完成风险初筛或结构化评审；缺失事实先补齐，再判断规则是否适用。
3. 查看需求分析、风险条目与引用依据，整理需要改进的功能和材料。
4. 生成文档草案，交由相应审查人员核实、修改并确认后再使用。

## 当前完成程度

- 研究与演示阶段：初筛、规则评审、分析报告和模板生成已具备代码实现。
- 示例工作区、日历和历史页用于演示；认证、持久化与外部模型在示例配置中默认关闭。
- 界面提供简体中文、繁體中文与 English，并保留语言选择；原始法源与已有生成文档保持原文。

## 快速开始

Node.js 20。复制 .env.example 为 .env.local，先保留示例功能开关为 false；未配置模型时，在需求分析页选择“规则引擎”模式。模型分析需另配置服务端密钥并将 FEATURE_LLM 设为 true。数据库迁移不属于普通启动步骤。

```bash
npm ci
# Copy .env.example to .env.local
npm run dev
# http://localhost:3000
npm test
npm run build
```

## 使用边界

- 规则命中不等于已履行义务，风险分数不等于法律结论；需结合适用法域、最新法源和真实产品事实复核。
- 不将内置收录数量、演示时间或模型输出写成覆盖率、准确率与效率承诺。
- 当前没有已验证的团队权限、长期审计记录或正式监管申报闭环；这些与原型页面分开建设。
